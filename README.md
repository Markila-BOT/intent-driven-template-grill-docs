# Intent-Driven Template: Grill Docs

An [OpenSpec](https://github.com/Fission-AI/OpenSpec) and [OpenCode](https://opencode.ai/) template with the `proposal -> specs -> design -> adr -> tasks` workflow enabled. The proposal step grills the plan and writes the documents it settles while the interview runs: glossary terms and architectural decisions.

This is a fork of [intent-driven-template](https://github.com/intent-driven-dev/intent-driven-template) that ships the grill-with-docs proposal flow, OpenSpec 1.16 lifecycle assets, and layouts for OpenCode, Codex, and Cursor.

## What Is Different From The Upstream Template

- The proposal rule is `grill-with-docs` instead of `grill-me`. `grill-with-docs` runs two skills together: `grilling` interviews you in rounds, `domain-modeling` records each settled term and decision immediately.
- Glossary terms land in `glossary/business.md` or `glossary/technical.md`, never in a spec or scratch file.
- Durable decisions land in `adr/NNNN-kebab-title.md`. Accepted ADRs are immutable; a later decision supersedes rather than edits.
- Lifecycle skills are generated by OpenSpec 1.16.0 and include `verify`, `new`, `continue`, and `bulk-archive`.
- Three tool layouts ship together: OpenCode, Codex, and Cursor.

## How To Use This Template

### Start A New Project

Clone this repository, open it with OpenCode, and start from the bundled OpenSpec configuration, commands, skills, and schema.

### Add This Template To An Existing Project

Open your existing project with OpenCode and ask it to install the template:

```text
Read and understand INSTALL_TEMPLATE.md in my local checkout of
intent-driven-template-grill-docs and follow the instructions there.
```

## Workflow

```text
proposal -> specs -> design -> adr -> tasks
```

- `proposal` captures why the change matters. `grill-with-docs` interrogates the plan and writes glossary entries and ADRs as decisions settle.
- `specs` describe observable behaviour with Gherkin-style scenarios.
- `design` explains the implementation approach and trade-offs.
- `adr` records durable architectural decisions under `adr/` and writes the change-local review manifest.
- `tasks` turn the accepted intent, behaviour, design, and decisions into work.

## The Documents The Interview Produces

| Output | Location | Purpose |
| --- | --- | --- |
| Business glossary | `glossary/business.md` | Domain, product, workflow, and business terms. |
| Technical glossary | `glossary/technical.md` | Architecture, implementation, platform, and protocol terms. |
| Decision record | `adr/NNNN-kebab-title.md` | One durable, hard-to-reverse decision with its context and consequences. |
| Glossary companion | `<artifact>-glossary-reference.md` | Which glossary terms an artifact uses, without copying definitions. |

The `domain-modeling` skill creates these files lazily. A repository with no glossary or `adr/` directory is normal until the first term or decision is settled.

## Repository Layout

| Path | Contents |
| --- | --- |
| `openspec/` | `config.yaml`, the bundled `intent-driven` schema, and its templates. |
| `.opencode/agent/` | `senior-dev`, `senior-qa`, `adversarial-author`, `adversarial-reviewer`. |
| `.opencode/commands/` | `/opsx-*` commands: new, propose, continue, explore, apply, verify, sync, update, archive, bulk-apply, bulk-archive. |
| `.opencode/skills/` | OpenCode copies of the lifecycle and collaboration skills. |
| `.agents/skills/` | Codex target copies plus the shared skills: grilling, domain modeling, glossary, ADRs, C4, TDD, acceptance tests, spec-as-source. |
| `.cursor/rules/openspec-schema.mdc` | Always-on Cursor rule for schema selection and skill resolution. |
| `openspec/schemas/intent-driven/` | The `proposal -> specs -> design -> adr -> tasks` schema and templates. |

OpenSpec maintains `.opencode/skills` and `.agents/skills` per tool target. Duplicate skill names across those two directories are expected; they are the same skill written for different agents.

## Skills

| Skill | Location | Purpose |
| --- | --- | --- |
| `grill-with-docs` | `.agents/skills/` | Runs `grilling` and `domain-modeling` together so the plan and its documents converge in one pass. |
| `grilling` | `.agents/skills/` | Interviews in frontier rounds, one design-tree layer at a time, with a recommended answer for every question. |
| `domain-modeling` | `.agents/skills/` | Challenges vague terms, sharpens them against the glossary, and records settled terms and ADRs. |
| `grill-me` | `.agents/skills/` | The interview-only variant, with no document output. Use it when a throwaway design conversation is enough. |
| `glossary` | `.agents/skills/` | Owns the glossary table format, companion reference files, and term consistency across artifacts. |
| `c4-diagrams` | `.agents/skills/` | Visualises system boundaries with C4 levels in ASCII or Mermaid. |
| `architectural-decision-records` | `.agents/skills/` | ADR styles, statuses, supersession, and the review checklist. |
| `gherkin-authoring` | `.agents/skills/` | Drafts observable Gherkin scenarios in domain language. |
| `spec-as-source` | `.agents/skills/` | Opt-in executable specs; requires `stack:` in `openspec/config.yaml`. See below. |
| `acceptance-test-authoring` | `.agents/skills/` | Runner, extraction, linting, and step definitions for `spec-as-source`. |
| `test-driven-development` | `.agents/skills/` | Red-green-refactor discipline, loaded by `senior-dev`. |
| `openspec-git-discipline` | `.agents/skills/` | Proposals reach `main` before apply; implementation merges before archive. |
| `adversarial-authoring` | `.opencode/skills/` | Author and reviewer agents in sequence to reduce single-model bias. |
| `openspec-*` lifecycle | both skill directories | new, propose, continue, explore, apply, verify, sync, update, archive, bulk-apply, bulk-archive. |

## Agents

| Agent | Purpose |
| --- | --- |
| `senior-dev` | Implements source work test-first through strict red-green-refactor. |
| `senior-qa` | Authors acceptance tests, step definitions, and runner configuration. |
| `adversarial-author` | Writes an initial draft of an artifact for review. |
| `adversarial-reviewer` | Challenges the draft before the primary agent writes the final artifact. |

Route source work to `senior-dev` and acceptance work to `senior-qa` from the `context` block in `openspec/config.yaml`. Do not batch their tasks; call them in small batches as development and test work interleave.

## Schema

`openspec/config.yaml` already selects the bundled [`intent-driven` schema](openspec/schemas/intent-driven/schema.yaml). OpenSpec honours that value when creating a change, so no extra flag is needed.

Adapt the schema only when the artifact order itself changes, not to tune wording.

## Experimental: Spec As Source

`spec-as-source` turns fenced Gherkin inside OpenSpec specs into executable acceptance tests. It is opt-in:

1. Uncomment the skill under both `specs` and `tasks` in `openspec/config.yaml`.
2. Record the runner stack: `stack: javascript` or `stack: python`.
3. Configure the runner with `acceptance-test-authoring`.

Enabling it changes the spec format: structure moves to Markdown headings and only Given/When/Then steps live in column-0 ` ```gherkin ` fences. Existing specs must be migrated before the extractor will accept them; a scenario without a fence is a hard error.

## Optional: Enable Superpowers

[Superpowers](https://github.com/obra/superpowers) adds guided practices such as brainstorming, planning, debugging, and worktrees. It is not enabled by default.

To enable it, add the plugin entry to `opencode.json` while preserving anything already there:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["superpowers@git+https://github.com/obra/superpowers.git"]
}
```

Restart OpenCode to load it.

## Keeping The Template Current

The lifecycle skills are generated files. After changing the installed OpenSpec CLI or the workflow profile, refresh them:

```bash
openspec update --dry-run
openspec update
```

OpenSpec may add or remove lifecycle skills to match the machine's workflow profile. That is expected; do not hand-edit generated skills.
